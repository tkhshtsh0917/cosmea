# SciFactを使った小規模ベンチマーク

[English](../benchmark.md) · [設計](design.md)

SciFactは、科学的な主張を入力とし、裏付けや反証となる論文の要旨を検索するデータセットです。この実験では、[BEIR版SciFact](https://github.com/beir-cellar/beir/wiki/Datasets-available)に収録された[SciFactの判断データ](https://github.com/allenai/scifact)を使います。データは[利用条件](https://github.com/allenai/scifact/blob/master/LICENSE.md)に従って別途取得します。

## 比較を実行する

[貢献ガイド](../../CONTRIBUTING.ja.md#セットアップと検査)に沿って開発環境をセットアップしてから、次を実行します。

```bash
mkdir -p outputs/scifact
curl --fail --location \
  --output outputs/scifact/scifact.zip \
  https://public.ukp.informatik.tu-darmstadt.de/thakur/BEIR/datasets/scifact.zip

mise exec -- env HF_HUB_OFFLINE=0 uv run --frozen --no-sync python experiments/scifact_benchmark.py \
  --data outputs/scifact/scifact.zip \
  --output outputs/scifact/reviewed-results.json \
  --train-pairs 256 \
  --data-seed 42 47 48 49 50 \
  --seed 42 44 45 46 48 \
  --timing-repeats 4 \
  --threads 4
```

乱数は一度に片方だけ変えます。まず最初のデータ抽出シードで256ペアを固定し、学習シードを変えます。次に最初の学習シードを固定し、データ抽出シードを変えて別のペアを選びます。共通する最初の組み合わせの評価は1回です。シードのリストと時間計測の反復を省くと、1組だけ実行します。

モデルを読み込む前に、標準MNRLのバッチ構成を検査します。データに重複があると、サンプラーがTrainerの予定より多くのバッチを作る場合があります。最初に試した学習シード43では、16ステップで256行中255行しか消費しませんでした。各比較では、42から昇順にバッチ構成だけを見て、消費行とステップ数が揃う最初の5シードを採用しました。結果はこの条件を満たす組み合わせについての記録です。

## データと評価

初回の抽出には、テストの正解文書を学習の正例に含むペアが74件あり、よく似た主張も含まれていました。再実験では公式テストの全300クエリ・339件の正解判断を維持します。公式学習の919ペアから、大文字・小文字と空白を正規化したクエリ本文がテスト側と一致する2件を除き、さらにテスト正解文書を正例に持つ293件を除きました。残り624ペアから学習用の256ペアを抽出します。

文書はタイトルと要旨をつなげ、全条件で同じ5,183文書をコサイン類似度で検索します。テストの正解文書もコーパスに残るため、ラベルを参照せず抽出する一様負例には含まれ得ます。テスト判断の用途は正例ペアの除外と品質評価です。この実験はSciFactのテスト正解文書を学習正例から除いた設定です。除外は本文と文書IDに基づくため、異なるIDで意味が近いテキストは残り得ます。

各条件は同じ[all-MiniLM-L6-v2のリビジョン](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2/tree/1110a243fdf4706b3f48f1d95db1a4f5529b4d41)から開始します。128トークンの上限は学習・評価のクエリと文書に共通で、初期モデルの評価にも適用します。この版のトークナイザーでは、5,183文書のうち5,073文書が切り詰められます。元のモデルの[既定値](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2#intended-uses)は256です。指標は二値の関連度を使い、クエリごとの値を等しく平均します。

## 学習条件

各シードの組み合わせの中では全条件で同じ256正例ペアを使い、1エポック、バッチサイズ16、初期学習率 `2e-5` で揃えます。

| 条件 | 行サンプラー | 既知正例マスク | 1バッチの一様負例数 | logQ補正強度 |
| --- | --- | --- | ---: | ---: |
| 初期モデル | — | — | — | — |
| A · 標準MNRL | `NO_DUPLICATES` | — | 0 | 0 |
| B · バッチ内の対照 | ランダム | 両方 | 0 | 0 |
| C · 一様負例の対照 | ランダム | 両方 | 16 | 0 |
| D · Cosmea | ランダム | 両方 | 16 | 1 |

標準MNRLはSentence Transformersの既定損失と[推奨サンプラー](https://www.sbert.net/docs/package_reference/sentence_transformer/losses.html#sentence_transformers.sentence_transformer.losses.MultipleNegativesRankingLoss)を使います。B・C・Dは、同じ正例バッチでCosmeaのpooled `plugin` を使います。実際に消費した学習行数と最適化ステップ数を検査し、C・Dで各バッチのクエリIDと候補IDが一致することも確認します。AからBではサンプラーとマスクが同時に変わり、BからCでは一様負例が加わり、CからDでは同じ候補にlogQ補正が加わります。

最初のシードの組み合わせで学習を4回繰り返し、実行順を2回ずつ入れ替えます。表の時間は `Trainer.train()` の実測時間の中央値で、開始処理、トークン化、最適化を含みます。モデルの読み込み、コレーターの準備、評価は計測区間外です。処理したテキスト量はパディングを含む入力トークン数で記録します。実行時間は文の長さ、バッチの組み方、ハードウェアにも依存します。

出力JSONには、採用したペアのID、ソースのコミットとハッシュ、クエリごとの指標、条件間の対応差、学習行数・ステップ数、反復ごとの時間とトークン数を記録します。

## 再計測の結果

2026-11-19にmacOS arm64、Python 3.12.13、Sentence Transformers 6.3.0、PyTorch 2.15.0、CPU 4スレッドで計測しました。共通の組み合わせを1回として、計9組を評価しました。各表は5回の平均と標本標準偏差です。初期モデルは同じ評価結果を参照します。

### 学習ペアを固定し、学習シードを変えた場合

| 条件 | nDCG@10 | MRR@10 | Recall@10 | Recall@100 |
| --- | ---: | ---: | ---: | ---: |
| 初期モデル | 0.6239 | 0.5784 | 0.7743 | 0.9227 |
| A · 標準MNRL | 0.6290 ± 0.0055 | 0.5854 ± 0.0069 | 0.7781 ± 0.0072 | 0.9223 ± 0.0051 |
| B · バッチ内の対照 | 0.6281 ± 0.0035 | 0.5846 ± 0.0042 | 0.7769 ± 0.0060 | 0.9220 ± 0.0040 |
| C · 一様負例の対照 | 0.6276 ± 0.0015 | 0.5843 ± 0.0019 | 0.7743 ± 0.0064 | 0.9247 ± 0.0099 |
| D · Cosmea | 0.6334 ± 0.0033 | 0.5880 ± 0.0033 | 0.7877 ± 0.0055 | 0.9207 ± 0.0038 |

### 学習シードを固定し、学習ペアを変えた場合

| 条件 | nDCG@10 | MRR@10 | Recall@10 | Recall@100 |
| --- | ---: | ---: | ---: | ---: |
| 初期モデル | 0.6239 | 0.5784 | 0.7743 | 0.9227 |
| A · 標準MNRL | 0.6279 ± 0.0120 | 0.5846 ± 0.0099 | 0.7762 ± 0.0194 | 0.9283 ± 0.0069 |
| B · バッチ内の対照 | 0.6281 ± 0.0095 | 0.5841 ± 0.0075 | 0.7789 ± 0.0153 | 0.9277 ± 0.0061 |
| C · 一様負例の対照 | 0.6285 ± 0.0074 | 0.5846 ± 0.0068 | 0.7783 ± 0.0106 | 0.9257 ± 0.0066 |
| D · Cosmea | 0.6327 ± 0.0042 | 0.5875 ± 0.0046 | 0.7867 ± 0.0051 | 0.9258 ± 0.0049 |

logQ補正単体の差（D−C）は、学習ペアを固定した場合にnDCG@10の平均で +0.0058、範囲は +0.0016〜+0.0098でした。学習ペアを変えた場合の平均は +0.0042、範囲は −0.0036〜+0.0157で、差の符号も変わりました。標準MNRLとの差（D−A）も、ペアを変えると −0.0077〜+0.0170でした。いずれの平均でも、今回の結果はシードとSciFactの評価条件に限られます。

A−BとB−Cは両方の比較でnDCG@10の対応差の平均が絶対値0.001未満でした。ランダムなバッチの同一正例文書の追加出現は、9組で1エポックあたり1〜6行、同じクエリは0〜3行でした。この集計はバッチ内の重複に関するもので、一様負例に適用するマスクの回数は含みません。

### 学習時間と処理量

| B · バッチ内の対照 | 4.85 (4.81–4.99) | 42,192 |

一様負例を加えたC・Dは、この設定で標準MNRLの約1.8倍の入力トークンを処理しました。Dの学習時間中央値はAの約1.8倍でした。CとDのトークン数は同じで、時間の範囲も重なりました。これらの時間はバッチサイズ16、一様負例16、入力長上限128での観測です。
